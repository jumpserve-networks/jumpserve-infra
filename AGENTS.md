# Repository guidance

Use Context7 for library/API documentation and configuration work. Prefer
connected tools and ordinary local checks; preserve unrelated local changes.

The user authorized the **Platform Development Supervisor OpenClaw** to merge
and deploy qualified improvements across the three JumpServe repositories after
initial activation. Its immutable Supabase authorization, fixed checks, protected
exact GitHub revisions, scoped AWS roles, limits and owner controls govern that
service. Do not overwrite evidence or weaken scientific
criteria to obtain a passing release. Preserve original uncertain outcomes and
reconcile their identities before dispatching replacement actions.

Keep ordinary interactive editing local unless the user explicitly requests
deployment of the current changes. The supervisor's standing authority does not
grant unrelated sessions blanket deployment permission. Follow
`docs/platform-supervisor-v1.md` for initial activation and release scope.

The owner now grants the named supervisor full standing operational authority for
unattended academic-paper reproduction, including worker skills/tools,
dependencies, instrumentation, experiment environments, JumpServe infrastructure
and service roles, Supabase migrations, runtime/self-repair, qualification,
merges, production deployment, verification and rollback, without further owner
questions or permissions. Missing technical capability is implementation work;
automate and qualify the necessary adapters instead of asking the owner to grant
the same authority again. Preserve cancellation, scientific criteria, original
evidence, privacy and reconciliation of uncertain calls. An authority record is
not evidence of installed capabilities or deployment success. Ordinary unrelated
interactive editing retains the deployment rule above. See
`docs/platform-supervisor-standing-authority-v1.md`.
