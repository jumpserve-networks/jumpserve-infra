# Repair-completion production release

This release supplies missing incident-binding metadata from the native builder
and delivers an explicit candidate-staging command. The server continues to
require changed source, executed incident tests, matching frozen packages and
fresh scientific reviews. Assessment budgets, deadlines, cancellation and
uncertain-call fences are unchanged.

Qualification uses a new isolated Linux/amd64 machine with the installed,
hash-verified production builder image and pinned Node/OpenClaw dependencies.
It receives an expiring access token from the existing production credential
owner, without copying or refreshing the OAuth grant. Synthetic tool execution
precedes a separate live model run with the unchanged 12-call allowance. The
original failed live trial is retained as failed. All setup failures and actual
qualification artifacts remain in private release evidence.

The live run completed in nine calls with server-validated source and an
unchanged prospective candidate. Its original harness report remains failed:
the matcher expected a standalone completion command and rejected the same
successful direct command after another checked script using `&&`. A separate
zero-call retained review verifies the paired incident-bound staging JSON,
original terminal streams, actual executed Docker checks and frozen package
hashes. The reader correction has regression coverage; no original outcome,
candidate, test, inference or experiment was rewritten or replayed. See
[the exact-source qualification](repair-completion-qualification-v1.json).

The runtime manifest binds the qualified executable files and derived approval.
The renderer updates six existing research Lambda code objects and exact
immutable executor bindings. Follow-up rendering requires the verified literal
predecessor ARN and network group; it cannot accept an arbitrary executor or
change placement. IAM, existing machines, storage, endpoints, stack parameters,
outputs and prior executor versions remain unchanged.

Production admission is held only for the coordinated switch, after active
calls and leases drain. The native runtime is installed as a physical directory
with a retained backup. Every runtime file is read back from all six Lambda
archives and the host before admission is restored. The temporary qualification
machine is terminated, its token object is deleted, and the final verified
release is recorded in private Supabase Storage and Platform Updates.

These are exposed software-development controls reviewed by the implementing
AI. A passing repair completion does not establish scientific correctness or
guarantee successful outcomes for every future paper.
