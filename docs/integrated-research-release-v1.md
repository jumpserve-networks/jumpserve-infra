# Integrated research runtime release

The integration retains current main's supervisor authorization, category
budgets, maintenance handoff and operational recovery adapter. Outstanding local
work adds native repair handoff, durable completion reconciliation, retained
bounded-executor responses and versioned 100-GB sampled-counter policies.

The runtime qualification binds 65 files to
`900bcf85ef0957bfc86934fad91b6a1b7fa593d67f9d0bdbd1104372b029169a`.
The private Linux evidence archive is 3,984,280 bytes with SHA256
`34a8a969c03268a73dbcdb89c699d7712f8fb9f3c0559a38c49347ac099354fa`.
Its location is retained in private operator records. See
[the source qualification](integrated-research-qualification-v1.json).

Validation includes 438 research tests, 26 supervisor tests, 11 benchmark tests,
297 frontend tests, 97 infrastructure tests (five optional checks skipped), four
release-renderer tests and 27 isolated SQL checks of funding, maintenance and
native reconciliation in the deployed migration order. Frontend lint/build and
the infrastructure TypeScript build passed. A local completion fixture confirmed
two claims sharing one acquisition, durable measurement ingestion and a real
process restart without replaying the executor. These are software controls,
not research findings.

AWS Linux qualification exercised seven synthetic native responses with actual
OpenClaw file/command tools and a server-executed repair validator. The fixed
namespace TCP smoke recorded ten observations. Controlled-counter checks cover
the exact 100,000,000,000-byte limit and termination above it; no actual 100-GB
transfer campaign or billing calibration is claimed. Current AWS Price List
responses support the conservative v3 reservations; measured charges remain
unavailable. Earlier cost-policy versions remain unchanged.

The original live repair trial used 12 provider calls. It changed the source and
executed tests but exhausted its qualification allowance before supplying the
completion metadata. **That trial remains failed.** A distinct zero-call control
verified its original request/terminal-stream hashes and the actual changed
source, then ran the server validator/compiler with explicitly fixture-supplied
metadata. The model did not declare a candidate. This qualifies the repair
implementation and validation path; it does not establish complete unattended
model behavior. No scientific criterion, assessment limit or original uncertain
outcome was changed to obtain a pass.

Qualification initially overlapped live workers and the host recorded a global
out-of-memory kill. The host was rebooted only after database verification of
zero active calls, live leases and release operations. Later checks ran serially
with both services stopped. Failed attempts, original reports and checkpoints
remain retained. Original research deadlines and usage remain unchanged.

The coordinated release changes six existing research function code objects,
the controllers' exact v3 policy/executor bindings and one hash-checked immutable
executor version. Earlier versions, IAM, machines, storage, layers, endpoints,
parameters and outputs are preserved. The native host receives the same verified
runtime bytes. Assessment-reset utilities are retained as source and are not
invoked. Production verification and restored admission are recorded separately.
